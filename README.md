# pizz0x — portfolio

Filippo Pizzo's portfolio: every public GitHub repository of [@Pizz0x](https://github.com/Pizz0x), kept up to date automatically, and the curriculum. English by default, Italian at `/it/`, both generated by machine translation.

## How it works

Three scripts run in order, every night and on every push to `main` (`.github/workflows/deploy.yml`):

| Step | Script | What it does |
| --- | --- | --- |
| 1 | `npm run fetch` | Lists the public repositories through the GitHub API, forks included (team projects: their page names the original repository; `includeForks` in `site.config.json` turns them off). For each one it reads the README (title, description, body), the file tree, the languages and the folders each one is used in, the date of the middle commit (its year is the one the site shows), every PDF (anything named *report* comes first), images in `docs/` or linked from the README, demo videos. Writes `.data/projects.json` and `.data/files/`. |
| 2 | `npm run translate` | Translates the interface (`content/ui.json`), the curriculum (`content/cv.json`) and every README into English and Italian. The source language is detected, so an Italian README becomes English too. Uses DeepL when the `DEEPL_API_KEY` secret exists, otherwise Google's keyless endpoint. Only new text is sent; the rest comes from `.cache/translations.json`. |
| 3 | `npm run build` | Writes the static site to `dist/`: home (project titles around the name, about me, where I studied and worked, a table of the projects), one page per repository (tags, languages and where they are used, structure drawing, README, documents with an in-page PDF reader), curriculum, 404, sitemap. PDF covers and video posters need `poppler-utils` and `ffmpeg`. |

A new public repository appears on the site after the next nightly run (or right away with **Actions → Build and deploy the portfolio → Run workflow**).

## Setup (once)

The site lives in the public repository `Pizz0x/pizz0x.github.io`, so it is served at `https://pizz0x.github.io/` (free GitHub Pages needs a public repository; this name gives the address without a sub-folder).

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. Optional, better translations: create a free DeepL API key and add it as the repository secret `DEEPL_API_KEY` (**Settings → Secrets and variables → Actions**).

The curriculum PDF in `content/cv/` is public too: keep the phone number out of it.

GitHub pauses scheduled workflows in public repositories after 60 days without commits; any push (or re-enabling the workflow in the Actions tab) starts them again.

## Changing things

- **Curriculum**: edit `content/cv.json` (English) and replace `content/cv/Filippo_Pizzo_CV.pdf`. Logos live in `content/logos/`.
- **Interface text**: `content/ui.json` (English only; Italian is generated).
- **A repository's title, discipline, description, tags or award**: `projects` in `site.config.json`. Keys are repository names; `hide: true` hides one (the repository stays on GitHub; set it back to `false` to show it again), `pin` orders the project table. The tags shown on a project page are its GitHub topics when it has any, otherwise `tags` there (kept as written, not translated). Adding the topic `portfolio-hide` on GitHub also hides a repository.
- **Disciplines and their colours**: `disciplines` in `site.config.json`. A repository gets the discipline named by one of its GitHub topics (`data-engineering`, `distributed-systems`, `machine-learning`, `graphs-and-models`), or the one whose keywords appear most in its README.
- **Contacts**: `contact` in `site.config.json` (email, GitHub, LinkedIn), shown under the name on the home page and in the footer.

## Working locally

To just look at the site: `npm install`, then `npm run preview`. It reads GitHub only the first time (or with `npm run preview -- --fresh`), then translates, builds and serves it at http://localhost:4321. Without `poppler-utils`, PDF covers are drawn with Ghostscript and ImageMagick if they are installed; without `ffmpeg`, videos have no poster frame.

Step by step:

```bash
npm install
GITHUB_TOKEN=… npm run fetch          # or: LOCAL_REPOS=../clones npm run fetch (a folder of git clones)
npm run translate
npm run build
npm run serve                         # http://localhost:4321
```
